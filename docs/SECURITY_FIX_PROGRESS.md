## Change log

- 2026-07-15: Started production remediation in risk order.
- 2026-07-15: Removed the startup database sanitizer from the deployable source tree. Disabled admin seeding by default and in SAM, rejected blank/known default credentials, and redacted the password from logs. Backend compile passed.
- 2026-07-15: Blocked ADMIN self-registration; enforced banned-user checks for login, refresh and access tokens; revoked refresh tokens on bans/role changes; blocked role changes with active obligations; blocked self-application. Seven targeted auth tests passed.
- 2026-07-15: Disabled deposit/withdraw cash simulation by default and in SAM; made missing escrow report as unfunded; added pessimistic row locks for users, tasks, escrows and application acceptance; added deadline recheck during acceptance. Eight targeted tests passed.
- 2026-07-15: Added task/submission/session ownership checks to AI flows; removed duplicate first chat message and sensitive email/wallet profile snapshots; restricted file extraction to approved HTTPS storage hosts, blocked private IPs/redirects, capped download/archive/pages/text, validated file signatures, and rejected unsupported image analysis; added AI/register/recovery rate limits with idle eviction. Six targeted AI/Bedrock tests passed.
- 2026-07-15: Enforced participant/admin visibility for submissions, revisions, evaluations, disputes, drafts and private files; made evaluation idempotent and task-scoped with validated weights/scores; allowed either participant to open a dispute but reserved resolution for admins; added private Supabase signed URLs and stored-object verification; restricted uploads by type, extension, signature and safe DOCX structure. Updated escrow-aware test fixtures. Forty targeted tests passed.
- 2026-07-15: Rebuilt milestone escrow as a coherent state machine: milestone totals cannot exceed the budget and must equal it before lock/funding; task escrow and milestone escrow are mutually exclusive; pessimistic locks prevent duplicate deductions/releases; all milestones must be funded before publish; submission marks open milestones submitted; rejection requests revision without refunding the hirer; admin-only refunds return principal plus fees; milestone release is idempotent and completes only after all payments release. Fourteen milestone/escrow/auth tests passed.
- 2026-07-15: Removed raw reset links and OTPs from logs; made recovery discovery non-enumerating; skipped undeliverable tokens when providers are disabled; added AWS SES security-mail support with scoped IAM; hashed SMS OTPs, locked rows and invalidated after five failed attempts; added Flyway V5 to invalidate legacy plaintext OTPs; made health verify the database; removed localhost production CORS and fixed Lambda origin reflection; tightened JWT/Bedrock production validation. Eighteen targeted tests passed and the SAM template validated.
- 2026-07-15: Frontend session refresh now uses a single in-flight refresh request, authenticated multipart uploads and signed private-file URLs; recovery supports direct reset tokens; milestone UI states match the backend revision flow. ESLint completed with zero errors and both client/SSR production builds passed.
- 2026-07-15: After an external overwrite of tracked backend files, re-applied and revalidated private submission/revision/evaluation access checks and the milestone escrow state machine. Added record locks, mutual exclusion between task and milestone escrow, exact budget totals, one-time release, revision-without-refund, and principal-plus-fee admin refunds. Thirty-three focused tests passed.
- 2026-07-15: Re-applied role/session protections after overwrite: active tasks and pending applications block role changes, role changes atomically revoke and replace refresh tokens, admin role changes revoke sessions, bans revoke every refresh token, and banned users cannot authenticate with an existing access token. Thirteen focused auth/JWT tests passed.
- 2026-07-15: Re-applied financial concurrency controls: direct cash simulation is disabled by default and in SAM, wallet/task/application/escrow rows are locked before mutation, accepting after the deadline and self-application are rejected, missing escrow is never treated as funded, task/milestone escrow is exclusive, admin dispute actions require ADMIN, either participant may open a dispute, and legacy or milestone releases are one-time. Twenty-four focused tests passed.
- 2026-07-15: Connected the real AI runtime to AWS Bedrock Claude Haiku 4.5 (controller, evaluation and criteria extraction), verified the model/inference-profile ID against current AWS documentation, added Lambda `bedrock:InvokeModel` permission and environment settings, made all non-public AI routes require JWT, and added bounded AI/auth rate limiting with idle bucket eviction. Fourteen focused tests passed and the SAM template validated.
- 2026-07-15: Fixed public search correctness and scale: task keyword/category/deadline filters now run in the database before pagination, page and sort inputs are bounded, freelancer review/task statistics are loaded in bulk using the correct review direction, and public search no longer exposes email. Broadcast delivery now pages through all non-admin recipients in 500-user batches instead of stopping at 10,000. Analytics date windows are bounded and repeated/N+1 queries were removed. Public profiles no longer expose another user's email, phone, wallet, earnings, ban state or birth date. Backend compile and five focused regression tests passed.
- 2026-07-15: Final verification completed. Updated legacy Phase 3 fixtures to include funded escrow, removed the stale compiled runtime-DDL runner left by a non-clean build, and passed all 115 backend tests. Frontend ESLint passed with zero errors (seven Fast Refresh warnings), client and SSR production builds passed, and SAM reported a valid template (its telemetry write was blocked outside the workspace after validation). A live AWS Bedrock Converse call to `global.anthropic.claude-haiku-4-5-20251001-v1:0` returned `TASKHUB_OK` using 25 total tokens with 1,201 ms service latency.
